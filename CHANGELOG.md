## [Unreleased]
### Added
- **A runbook for migrating off Claude without losing anything** (doc 120). Answers the real friction of leaving a paid Claude Code Pro subscription: your whole account history exports in one click (Claude.ai → Settings → Privacy → Export data — every conversation from day one, no date needed), and **`./securax knowledge import`** (doc 51, already built) turns that export into one redacted `.md` per conversation to upload into **Open WebUI → Knowledge** or **AnythingLLM** — your Claude Projects, private and on your own models. It maps the estate's three surfaces to Claude's (Studio = Code, Open WebUI = home + Projects, with the knowledge tab optional), shows how **MCP** collapses them toward one window, and gives the keys/secrets plan: inventory first (the queued `./securax keys`), consolidate into Vaultwarden, then **OpenBao** — the open-source HashiCorp Vault already in the estate via `./securax grow sprout`. Almost every step is **zero Claude tokens**; the three connective tools are specced for Studio to build on your own models (`migration-tools`). Also: a troubleshooting note in doc 119 for when `hub.<domain>/studio/` shows the Life OS (the running container predates the route — `./securax update && ./securax up`).
- **`./securax studio` — build the estate from a browser, on your own models (no Claude, no terminal)** (doc 119). The biggest friction to sovereignty was that changing SecuRAX meant a terminal *and* a paid Claude Code subscription — a single point of failure over the whole point of the project. Studio puts **VS Code with the Cline AI coding agent** in your browser, pointed at **your own gateway** and the open models you already run: you edit files, run commands, use git and MCP connectors, and the agent writes code — from a familiar GUI, on **zero Claude tokens**. It is an **opt-in add-on** with its own profile, **never part of `./securax up`**, so it can never affect your running estate; it is reached by name at **`https://hub.<domain>/studio/`** through the edge, binds to loopback only, and is **secure by default** (a strong password is generated on first start, since it can run code). `./securax studio [open|status|down]`. This is the usable first version (shipped *build usable today, harden after*): the queued hardening — a non-root container, a `code.<domain>` subdomain option, sign-in through the gateway's identity, a sandbox journey, and a digest-pin watch — is tracked in the backlog (`studio-harden`), and a standalone `docker run` fallback is documented for the first run. The companion to doc 118 (same open models, from the command line).
- **`./securax insight` — one durable idea a week, aimed at a goal you set** (doc 115). The companion to `improve`: where `improve` changes your *environment*, this sharpens your *thinking*. One timeless, high-leverage idea a week — decision-making & leadership, security & AI-risk craft, mental models, or money & financial independence — paraphrased in plain words with its **source named** and **one concrete action**. It is deliberately **not a feed**: no live source, no network, no scraper (which would manufacture the very noise you're escaping), but a **bounded, curated, on-device library** (`governance/insight.json`). It **aims by your OKRs first** (the lowest-progress goal whose theme it can match), then your weakest Wheel area, then rotates — and a per-machine seen-ledger means it **never repeats** an idea until its theme is exhausted (falling back to a weekly rotation if that ledger can't be written). The weekly `insight` routine sends it on **Wednesday mornings**; nothing about your goals or what you've seen ever leaves your box. This is the "brutal signal-from-noise" answer to a regulator dump: one aimed idea, one action, every week. Tests: `test_insight` (the OKR-first aiming order, the never-repeat guarantee, the honest fallbacks).
- **`./securax selftest` — prove every command works, before you need it** (doc 117). After the estate failed to even start, the honest answer to "do all these commands actually work?": it checks the **whole command surface with no side effects** — every command the CLI advertises is **wired** (can never print `unknown command`), the **code behind each one loads** (a syntax error, bad import or missing file is caught here, not when you type it in anger), and the **read-only commands** (`status`/`check`/`--json`/`list`/`help`) are **actually run** and must finish without throwing (a traceback or shell error is a failure; a clean "nothing set up yet" is not). Nothing that changes state is ever executed; a missing service dependency is reported, not failed. It exits non-zero on any problem, and **`test_selftest.py` runs it on every change in CI**, so a command that stops loading **fails the build** before it can reach you. `./securax selftest [--quiet|--json|--no-probes]`. Extending the probes to subcommands and a weekly report are queued (`selftest-subcommands`).
- **"Choose who you serve" — a new core principle, baked in forever** (doc 116). The Price Club / Costco lesson, read correctly: not "repel customers to make money" but **serve one clearly-chosen customer completely instead of everyone shallowly** — the membership fee is an honest *self-selection mechanic*, which is why ~9 in 10 Costco members renew. Added as a **core** principle in `governance/principles.json` (`choose-your-customer`), so it propagates to **every** app from the OS kit and every future product (enforced by `os check` and `kit1.js`). The playbook (doc 116) carries the default **barbell** model (a high margin from a chosen few — UHNW/HNI/enterprise — funds low-friction reach to many, Jio-style, with cost-to-serve near zero), a market-**sequencing score** (`ability_to_pay × margin × repeat ÷ cost_to_serve × friction × time` — win fastest and cheapest first), an **ICP template** every product fills before a line is built, and a reusable **prompt-engineered directive** that steers every product brief and autobuild spec. Two guardrails are written into the principle so it can never be misused: the **free safety core stays free for everyone**, and the mechanic is **honest friction, never a dark pattern or a denial of safety**. A fitness/suite guard that makes every product *declare* its chosen customer is queued (`icp-declared`).
- **`./securax improve` — one lever a week, aimed at your weakest Wheel-of-Life area** (doc 112). Instead of a feed to wade through, one calm nudge a week: it reads the **Wheel of Life** you scored in the quarterly check-in, finds the area you rated **lowest**, and gives you the single **set-and-forget** change that moves it most — its one-time steps and its if-then plan, from the environment catalogue and the behavioural / elite-sport research — rotating the lever week to week so it never goes stale. The weekly `improve` routine sends it to your phone on **Saturday mornings**. It reads only the wheel you already scored, on your machine; nothing leaves your box, and if you have not scored your wheel yet it says so and points you to the five-minute check-in. This is the "useful intelligence that improves the person" answer to the regulator-dump noise — signal aimed where it helps you most.
- **An SOP for finishing work on the estate with your own open models, not Claude** (doc 118). A step-by-step playbook for driving changes through `./securax autobuild` / `opencode` on the integrated open-model BUILD ladder (OpenCode Go + local Ollama) — the universal `route → brief → autobuild → verify → ship` loop, ready-to-paste commands per task, and the rule to reserve Claude for the strong-tier 20% and its review. The estate's own gates (`verify`, `fitness`, `selftest`, `suite check`, `ui_audit`) make it safe to let the open models drive. This is the practical answer to "I keep exhausting my Claude session": offload the bulk to the models you already pay a flat rate for.
### Changed
- **Sandbox: the `phone_device` journey retries a transient first-navigation flake once.** The journey intermittently failed with `net::ERR_NETWORK_CHANGED` on the *first* device's first `page.goto` to the HTTPS hub — a transient Chromium network re-config that cleared on a re-run (the iPhone opened the same page fine moments later). It now retries that one navigation **once**, and **only** on `ERR_NETWORK_CHANGED`; every other navigation error is still reported as the real refusal it is. Test-harness robustness only; no product change.
- **Phone alerts: signal, not noise (less alert fatigue).** Three sources of chaotic ntfy notifications are quieted, because a phone that cries wolf trains you to ignore the one alert that matters. (1) **"Unusual AI key use" no longer fires on a new model.** The gateway flagged "a caller asked for a model it never used before" as a possible stolen key — but that trips every time you add a provider or the resilient model-ladder tries a new rung, so it turned the whole estate RED for a normal action. Only genuinely behavioural signals — a request **burst** or activity at an **odd hour** — now raise that alarm; a new model is recorded, not alarmed. (2) **The autopilot stops narrating every routine blip.** A single failure of a self-healing routine (a sync hiccup, a feed down for a minute) now draws a postmortem draft **silently** instead of pushing "Routine X failed" then "Routine X green again"; you are paged **only** when a routine keeps failing (3 times in 7 days), with the one command that starts a fix. Recoveries ride the weekly progress message, not your phone. (3) **The regulator watch stops dumping titles daily.** It fetches the RBI/SEBI feeds silently; the **monthly** `regwatch digest` sends a curated summary and a genuine deadline still shows on the cockpit's Regulatory clock. Tests updated: `test_cockpit_priority` (a new model alone is not a stolen key; a behavioural anomaly still goes RED), `test_autopilot` (a blip is drafted silently; a recovery is recorded, not pushed).
### Fixed
- **The public website can't silently go dark again (GitHub Pages self-enables).** The site 404'd because `actions/deploy-pages` returns 404 ("Ensure GitHub Pages has been enabled") whenever Pages is not enabled at the API level — which regressed even though the built site was fine. The `docs` workflow's build job now runs `actions/configure-pages@v5` with `enablement: true` (granted `pages: write`) before uploading the artifact, so the workflow **turns Pages on itself** — no dependence on the Settings → Pages dropdown being set, and idempotent when it already is. One less recurring manual step nobody owned.
- **Life OS: impossible numbers, an unreadable phone card, and a phone that cried "sync failing" when it was simply offline.** Four daily-use fixes so the Life OS can be trusted for day-to-day use. (1) **Impossible figures are no longer taken as legitimate.** A value out of its plausible range already drew a warning, but the arithmetic still *used* it — so an age typed as 200, or expenses typed in a different unit from income, drove the benchmarks and vitals. A new `saneNum()` now **clamps** every such value to its field's real range before any calculation (an age of 200 computes as 100; the warning still shows you to fix it), so an impossible input can never produce an impossible result. (2) **The savings rate can no longer read `-567%`.** A rate below −100% or above 100% is not a real rate, it is a data-entry slip; the vitals tile now shows **"check"** (and taps through to the profile to fix it) instead of a nonsense percentage, while a genuinely negative rate down to −100% (spending more than you earn) is still shown honestly. (3) **The daily-three card is readable on a phone again.** The three tiles were crammed side-by-side at ~⅓ width each and the floor line ("Shoes on, one set. That counts.") was clamped to two lines and clipped; on a phone they now **stack vertically at full width** and the floor text wraps in full. (4) **"Sync pushes are failing (5576 in a row)" is now a calm "Working offline".** A phone is away from its estate most of the time, so "can't reach it" is the normal case, not an alarm: when the estate is simply unreachable the health screen says **"Working offline — will sync when your estate is reachable"** (no scary running count), and only a genuine refusal (the estate is up but rejects the push — a token/permission problem) is shown in red. Tests in `test2` cover the age clamp, the flagged saving rate, and both sync states; a real-browser check confirms the daily-three floor text renders in both themes at phone width.
- **A stopped add-on could show a GREEN "running" dot on the home screen — a status-integrity bug.** Behind the HTTPS edge the home page reads each service's real status from `/_up/<name>` (a 502 shows "not running"), but on a plain `http://localhost` address there was **no** `/_up/`, so the fallback did a `no-cors` fetch and painted the dot **green whenever the request resolved** — which it does even for a 502 or an error page. So a service that was actually down could look healthy. A status light that lies is worse than the outage: it breaks trust in every other light. Fix: the **plain `:8088` server now serves the same `/_up/<name>` probe** (`guiding-map.conf`, mirroring the edge), so the home screen reads the **real** status on every address — a running service is green, a stopped one is grey/red, and the hub's own dot is confirmed by a readable same-origin response. A green dot now **always** means a confirmed "running"; a service whose status genuinely cannot be read (a cross-origin app with no probe) shows a grey ring ("unverified"), never a false green. Test `test16` asserts real status on plain HTTP (a down service is never green) and the sandbox `ui_guiding_map_and_hub` journey proves it in a real browser.
- **The whole estate could not start — `no such service: gateway-tls` — and even rollback failed.** Running `./securax tls on` (which can happen on a cert renewal or re-apply) reset `COMPOSE_FILE` and **dropped `tls-internal.yml` while leaving `TLS_INTERNAL=1` on**. `up` then trusted the flag and asked Docker for `gateway-tls`, `litellm-tls`, … — services that live **only** in the dropped `tls-internal.yml` — so every start died with `no such service`, and because the broken setting lives in `.env` (user state, not code) the automatic rollback to the previous version failed identically. Three fixes, defence in depth: (1) **`tls on` now preserves internal mode** (keeps `tls-internal.yml` in `COMPOSE_FILE` when `TLS_INTERNAL=1`), so the drift can't be created; (2) a new **`./securax tls reconcile`** makes `COMPOSE_FILE` match the TLS flags, and **every `up`/`update`/`go` runs it first**, so an already-broken estate (and a failed rollback) **self-heals** on the next start; (3) a true last-resort **Fallback 3** brings the estate up in plain `http://localhost` mode when HTTPS can't start, so you are **never left with nothing running** (your HTTPS settings are kept; `./securax tls on` re-enables). The reconcile call is also made resilient to a broken or missing `python3`: because `securax` runs under `set -euo pipefail`, a non-zero command substitution in an assignment aborts the script, so a failing `python3` there would have stopped the estate from starting at all — it is now guarded (`|| true`) so `up` always proceeds. Immediate recovery on an affected box: `./securax tls internal on && ./securax up`. Tests: `test_tls_reconcile` (the repair, the preserve, the wiring, the fallback, and that reconcile can never abort `up`).
- **The Command Center went offline (403 Forbidden) after a life-docs import.** Writing the private `portal/inbox-import.json` chmod'd the *whole* `portal/` directory to `0700`. But `portal/` is also served by the Command Center's nginx (a different container user), so once it was owner-only, every page under it — the cockpit, the explainer — returned **403 Forbidden** (nginx `open() … 13: Permission denied`: a `0644` file is unreadable when a parent directory loses its `o+x` traversal bit). The private file is already protected at the file level (`0600`); locking the shared directory was both unnecessary and breaking. Now a private write never tightens a *served* directory (only the private `vault/` tree), and `./securax cockpit` — which `up` runs on every start — **self-heals** `portal/` back to `0755`, so an estate already in this state repairs itself on the next start. Regression tests assert the invariant (`test_lifebook`, `test_cockpit`).
- **`./securax autobuild` / `build` couldn't install its agent on modern Debian/Ubuntu.** The printed `pip install --user aider-chat` fails with PEP 668 `externally-managed-environment`. The agent now installs into a private, managed venv at `~/.securax/aiderenv` automatically (no system Python changes, no `sudo`), is reused from there on later runs, and — if that can't be created — prints install commands that actually work on a PEP 668 system (`pipx`, `apt install python3-venv`, or the `--break-system-packages` override).
- **Sandbox: the `blockers_are_explained` journey crashed intermittently.** It bound `127.0.0.1:8088` to simulate a port clash immediately after `sb.down()`, but Docker releases a published host port a moment after the containers stop, so the bind raced and failed with `[Errno 98] Address already in use` — a test-harness defect that read as a product failure. It now waits for the port to be free before taking it, and sets `SO_REUSEADDR`.
### Changed
- **Visualization honesty: charts that pass every check but lie to the eye, fixed** — the broken money Sankey was one instance of a class that slips through thousands of green checks (contrast, no page errors, no NaN) because those checks measure mechanics, never whether a chart *communicates*. Two more instances fixed in the OS-kit (Vantage): the **Wheel radar** drew an unscored area at 0.3 — a near-zero crumple that read as "my whole life is a catastrophe" when the truth was *"not scored yet"*; it now draws the filled shape **only when every area is scored**, shows a dot per scored area otherwise, and stays an empty outline until then. The **scorecard sparkline** auto-scaled to fit, so a 0.1 wiggle looked like a cliff (a high "lie factor"); it now carries its real **lo–hi range** and says **"flat"** when nothing moved. A new guard, `guiding-map/tests/kit2.js` (**visualization honesty**), renders every kit chart with the degenerate-data family — nothing / partial / all-equal / full — and asserts each one tells "no data" apart from a real low value and never exaggerates the effect it shows (Tufte's lie factor ≈ 1). Grounded in Tufte (lie factor, data-ink), visual-regression practice (edge-case datasets), and the BlackBerry/RIM lesson: passing your own checks means nothing if the human-facing output is broken.
- **The Life OS money view, redesigned** ("Where the money goes"): the old Sankey was unreadable (degenerate curves, crammed labels). It is now a single **100%-stacked bar** — your whole take-home split by share, wiping in left-to-right — with a clean legend (₹ and %), and three **healthy-band meters** (Fixed costs, Saving & investing, Guilt-free) that fill to where you are and turn green inside the band, amber/red outside. Tasteful reveal/grow animations (respecting `prefers-reduced-motion`), and segment colours chosen to pass contrast with white labels in both themes.
### Added
- **"Go live today" — the runbook to stop building and start living** (doc 114): the shortest honest path from "built" to running SecuRAX for real and letting it run itself, with no dependency on a paid Claude subscription. It states the true shape (an always-on box is the engine; the phone is the remote control and Life OS), then four parts: go live in fifteen minutes (`./securax go`/`ready`/`doctor`/`open`/`sync-link`); cut the cord to Claude (add an open-model key with `./securax providers add opencodego`, prove one `./securax autobuild` lands green with no Claude, turn on the unattended `pr-watch` loop); the twenty-six self-maintenance routines already running (safe nightly self-update with automatic rollback, daily backup + offsite mirror, restore drills, the autopilot learn/drill/forecast loop); the two-minute daily human loop; and what to do if something breaks (the estate heals itself first). Every command in it is verified to exist.
- **"This week your estate had your back" — the positive half of the Life OS home** (doc 93): the home now shows, up front (not folded away), a card of what the estate quietly did *for* you lately — kept a safe encrypted copy of your estate, watched every check with nothing red, turned failures into fixes, proved restores really work, added new things you can use. It is drawn **only from real events the estate already recorded** (`./securax lifefeed` now writes a `wins` array from the cockpit, your backups and `./securax progress`'s antifragility counts) — no amounts, no names, nothing invented, and nothing shown when there is genuinely no good news. The Sunday phone message (`./securax progress --send`) now leads with the same "had your back" frame. Small wins, shown — the north star made visible.
- **The lazy path: one tap files it, and 'Later' defers without guilt** — the Inbox no longer assumes a disciplined user. After a scan or a typed line, the lens offers a single **✓ Add it** button that files the item fully decided (kind, area, due date, next step) with no typing and no choices; an item with no date gets a gentle default so nothing sits in a growing "to decide" pile. Every item carries a one-tap **Later** that pushes it a few days out and clears it from view — procrastination is handled by the system, not punished. The "set a step & date yourself" controls are still there, folded away for when you want them. This closes the gap between the north-star principle ("least effort for the person") and a flow that used to demand a decision on every item.
- **The lens: it understands what you capture, and spots scams — on your device** (doc 104 §7): whatever you scan or type is read in the browser with no upload — classed (bill, policy, ID, appointment), its amount and due date pulled out so the item arrives already dated, and any scam signal (an OTP request, a "KYC blocked" message, a UPI collect-request) flagged with a red banner and the reasons in plain words. It **learns on the phone** from your "scam / safe" taps (bounded `gm_lens_model`, nothing leaves the device). Built as a **lens engine** (`gmLensRegister`) so future senses — ambient voice, compare-two-offers, a family lens — plug in with the same shape, no engine change. This is the SixthSense idea made private and security-grade: point at the world, get a decision you can trust.
- **Scan a paper with your phone's camera** (doc 104): the Life OS Inbox has a **📷 Scan a document** button. Photograph a policy, bill or letter and the text is read **on the phone itself** — the OCR engine (tesseract.js) loads once and is then cached for offline use — and dropped into the capture box to become a dated action or a note. Nothing is uploaded; the photo and its text never leave the device, and if the engine cannot load, capture by hand is untouched.
- **`./securax map` — see the whole estate at once** (doc 113): an interactive picture of the AI estate, generated from its own `features.json` and `governance/suite.json` so it can never drift out of date. Every component is a node coloured by what it is for; every shared platform service (identity, audit, policy, residency …) is a hub; an edge joins a component to each service it is built on — the "built for one, ready for many" story (doc 97) made visible. It is a **live force graph** — drag any node and the ones it links to trail after it like beads on a thread (a second-brain graph view, built in vanilla JS); tap for detail, hover to highlight, filter by area or search. It is **one self-contained HTML file** — no library, no network, no build step — so it opens on a phone or a laptop, online or off, in light or dark. A Command Center link and resilience/compliance overlays are queued.
- **`./securax environment` grows into the Wheel of Life, with the elite-sport levers built in** (doc 112): the set-and-forget catalogue now maps every change to a Wheel-of-Life area (health·sleep, health·body, finances, career, relationships, environment, fun & recovery, personal growth) — twelve struggles, including new `move` (a daily walk), `career` (a protected weekly skill/reach-out/win block), `space` (a 10-minute daily reset) and `rest` (protected, periodized recovery). Each entry now carries an **if-then plan** (implementation intentions — the single best-evidenced behaviour lever) and, where it's a habit, a **start-small floor** (the two-minute rule / deliberate-practice edge). Filter by struggle or by a weak Wheel spoke (`./securax environment finances`). Process-based scoring and a marginal-gains compounding view are queued for the Life OS surface.
- **Success by design: four new core principles + `./securax environment`** (doc 112). The estate now treats the undisciplined person — distracted, out of willpower, short on skill — as the spec, not the disciplined one. Four core principles added to `governance/principles.json` and propagated to every app via the OS kit: **best-default** (offer the fewest best options, pre-select the best, never a blank field), **shape-environment** (change the setting, not the willpower; a one-time set-up the environment enforces), **worst-day** (build for the worst day and it works for everyone), **aim-at-success** (design for the win, not only the disaster avoided). `./securax environment` is the first concrete catalogue: it reverses eight common struggles (can't focus, doomscrolling, no savings, late fees, debt, no routine, drifting from people, hard to read) into one obvious set-and-forget change each — phone grey and quiet at night, autopay every bill, pay-yourself-first on salary day — with the one-time device/account steps. A one-tap Life OS screen is queued (`environment-pwa`).
- **`./securax next` — the one command to remember** (doc 93): for a non-technical owner, a product with 123 commands is a wall. `next` reads where you are — estate running? life papers read in? safety setup finished? — and prints exactly **one** next step in plain words: the command, why, and what you will see. No list, no jargon. `./securax go` now ends by printing the same next step, so after every start you know the one thing to do. It reuses `./securax finish` and the Life OS import ledger, never inventing a check of its own.
- **The build's own single point of failure is now visible** (doc 23): `./securax ai share` warns when, over the window, the open models wrote none of the commits while Claude wrote some — so only one external AI can change the estate. It names the cause (the CI secret `OPENCODE_GO_API_KEY` unset, so `autobuild` and the open-model review never run) and the one step to clear it. The warning disappears the moment the open models land a commit.
- **The product site shows what is new by itself**: the homepage now carries a generated "Recently shipped" strip, newest first, from the one `features.json`. Adding a feature surfaces it on the site the same day — no page is hand-updated, so the showcase can no longer drift behind the feature count.
- **Adversary ledger — learning from a bug-bounty program** (doc 30): `./securax adversary` turns every bounty or red-team finding into a permanent regression. The raw finding stays private in the findings register; the public ledger records the finding's *class* and its permanent defence — a purple-loop probe (or a test), a lesson and a drill. `./securax adversary verify` (wired into `./securax verify`) refuses any finding not reproduced as a probe/test that really exists, any closed one without a lesson, and any class that recurred after it was closed (the **repeat-class rate**, which must stay 0). `./securax adversary status` and `./securax progress` show findings closed, repeat-class rate and days-to-regression, so a board sees the bounty spend compounding. Seeded with `ADV-0001` (history/memory poisoning, closed) as the worked example.
- **The purple loop probes every AI risk category** (doc 105, G5): all ten OWASP LLM and ten Agentic categories, plus bias and toxicity, each attacking the control that claims it (identity, allowance, stop switch, tool policy, fail-closed detectors, poisoned context, weights, skills, honesty). The report opens with a coverage table: 19 of 22 hold; the open gaps are named with the item that will close them (G5b, G15) and never counted as passes. `./securax purple` fails on an unprobed category or an attack that stops alerting.
- **Build from a phone with the open models** (doc 83, section 7): `.github/workflows/autobuild.yml` runs `./securax autobuild` in CI from *Run workflow* or an owner's issue labelled `autobuild`. OpenCode Go models do the work (the strong chain for hard work), the estate's gates decide, and a green result becomes an `autobuild:` PR with its checks running. The agent holds no write token and cannot fetch web pages. In October Claude made 92% of the commits, because the open-model tools ran only in a laptop terminal.
- **The rest of Claude Code's toolkit, on the open models** (doc 83): specialist OpenCode agents in `.opencode/agents/` (planner, test-writer, code-reviewer, security-reviewer, docs-keeper), and `.github/workflows/ai-review.yml`, an open-model review kept as one comment on every pull request.
- `./securax ai check` (doc 105, G4): every local model against its approved digest (the shipped defaults are approved in the model registry; `--approve` keeps your own, privately), and `--scan` finds pickle code in weight files without loading them.
- AI incident runbooks (doc 105, G11): `./securax incident runbook`, and `incident open --kind ai-data-leak` (or jailbreak, abuse, poisoned document) starts the clocks that kind usually needs and prints the first moves; the `ai-incident` tabletop checks the stop switch and the clocks on this machine.
- Two machine-checked maps (doc 105, G12a): `./securax comply owasp-ai` (OWASP LLM and Agentic Top 10, 20 categories) and `./securax comply free-ai` (the RBI FREE-AI report's 26 recommendations), also in `./securax readiness`.
### Security
- **History and memory poisoning closed** (doc 105, G10; OWASP ASI06): the gateway now inspects the whole conversation — earlier `assistant` turns and any chat memory replayed into the prompt — like any untrusted input, so an override planted in a prior turn is blocked instead of trusted for wearing the model's role.   the new service worker takes control, so you never get stuck on a stale old version in the cache.
- **Clear WSL vs Windows guidance.** `START-HERE-Windows.bat` typed inside WSL gives "command not
  found"; docs + the Command Center now say to use `./securax up` in a terminal and only double-click
  the `.bat` in File Explorer. Added troubleshooting for "models won't list / old version after pull"
  (the containers need `./securax down && ./securax up` to recreate — a pull alone doesn't).
- **Models now work out of the box.** The `modelplane` network was `internal: true`, so Ollama
  couldn't pull models and LiteLLM couldn't reach cloud models — breaking every answer. Given egress
  (models still publish no host ports). LiteLLM now defaults to **fast cloud Gemini with a local
  fallback**, so answers are instant with a free key and private-local otherwise.
- **No more false "Blocked by the guardrail".** Llama Guard was enabled by default but its model
  wasn't pulled, so the fail-closed detector blocked *every* request. It's now opt-in; the fast
  deterministic rails (100% red-team defence) run by default. The PWA also stops mislabeling a
  model-unavailable error as a guardrail block.
- `fin_freedom.py` argparse crash from a literal `%` in help text (Python 3.14).
- The optional kind/k8s plane used host port 8080, clashing with the gateway; moved to 8081.

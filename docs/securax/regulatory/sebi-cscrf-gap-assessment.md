# Gap assessment — SEBI Cybersecurity and Cyber Resilience Framework (CSCRF) for SEBI Regulated Entities

> Standard-level assessment of the estate against the SEBI Cybersecurity and Cyber Resilience Framework (CSCRF). 'entity' rows are obligations of the regulated entity that software cannot discharge. SEBI categories: MII, Qualified RE, Mid-size, Small-size, Self-certification.

Source: [SEBI Cybersecurity and Cyber Resilience Framework (CSCRF) for SEBI Regulated Entities](https://www.sebi.gov.in/legal/circulars/aug-2024/cybersecurity-and-cyber-resilience-framework-cscrf-for-sebi-regulated-entities-res-_85964.html) — Circular SEBI/HO/ITD-1/ITD_CSC_EXT/P/CIR/2024/113, 20 Aug 2024, read with the clarifications of 31 Dec 2024 (CIR/2024/184), 30 Apr 2025 (CIR/2025/60) and 28 Aug 2025 (CIR/2025/119) and SEBI's June 2025 FAQs; read 2026-10-14. CSCRF is a circular, not a Master Direction. Standards (e.g. PR.AA.S1) are grouped where the guideline block groups them. Applicability is taken from the guideline tables in the circular; later circulars and the entity's category assignment can change it. Obtain the entity's category and check for SEBI circulars issued after 28 Aug 2025 before relying on this.

Applicability scope: all layers / categories (use `--category` to narrow).

**Software-scope coverage: 47.3%** of 55 requirements software can address (✅ 1 supported · 🟡 50 partial · ⬜ 4 gap), plus **16 obligations that belong to the regulated entity** (🏛, never counted as covered by software) and 4 not applicable (➖).

> This is **not** a compliance certification and a tool cannot make an entity "100% compliant"; it shows what the estate demonstrably does, what it does not, and what only the entity can do.

## Backlog — what to build or fix, highest priority first

- 🟡 **DE.CM.S1-S3** (high) Continuous security monitoring and alerting; SOC services (own, market SOC, or third-party; small and self-cert on market SOC); SOC functional efficacy measured (Annexure-N) half-yearly; BAS/CART/decoy; MII 24×7 C-SOC — The AI-SOC triages gateway events 24×7 in software with ATT&CK/KEV enrichment, and the purple loop measures detection of known attack types. It is not a staffed SOC, does not cover endpoints/network beyond the optional Wazuh organ, and Annexure-N efficacy is not computed. **Next:** Compute Annexure-N efficacy indicators from the purple-loop results; add decoy/canary tokens.
- 🟡 **PR.AA.S16-S17** (high) API security (rate limiting, authentication/authorisation, OWASP API Top 10, whitelist connections); mobile-application security (root detection, anti-tamper, device binding...); SOPs for open-source application security and Generative-AI security (MII, QRE) — Gateway: authentication and authorisation (when enabled), rate limiting, request-size limits, prompt-injection and PII rails, output link allow-list, tool-call inspection; mapped to OWASP LLM Top 10 and ATLAS. Container-to-container hops on the private Docker networks, local volumes and backups are still unencrypted; no data-in-use protection. **Next:** Internal hops: `tls internal on` is available (exceptions in doc 40; Postgres is not used) - make it the default under the regulated profile; encrypt backups; document LUKS/FDE for the burrow.
- 🟡 **PR.DS.S4** (high) Data protection, backup and recovery; admin rights off by default on workstations; no sensitive data in client-side storage; renew certificates; control macros; data-migration policy — Backup and restore are proven; endpoint admin rights, macros and certificate renewal are the entity's; backups are unencrypted. **Next:** Encrypt and checksum backups.

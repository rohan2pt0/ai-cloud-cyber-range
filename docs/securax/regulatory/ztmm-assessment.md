> The CISA Zero Trust Maturity Model v2.0 (five pillars — Identity, Devices, Networks, Applications & Workloads, Data — and the three cross-cutting capabilities) assessed against what the SecuRAX estate demonstrably does. SecuRAX RUNS and GOVERNS an AI estate, a cyber range and a personal Life OS on one box; it is not an endpoint-management (MDM/EDR) product, so several device-pillar functions belong to the organisation that owns the laptops and phones, not to this software. Each title is CISA's function name; the notes are our own assessment and can be wrong: challenge them.

Source: [CISA Zero Trust Maturity Model v2.0](https://www.cisa.gov/zero-trust-maturity-model) — US Cybersecurity & Infrastructure Security Agency (CISA), April 2023; read 2026-10-29. Pillar and function names are from CISA's published model; the four maturity stages (Traditional/Initial/Advanced/Optimal) are not scored per-stage here. Status is our own judgement of a single-box lab estate, not a CISA assessment.

## Backlog — what to build or fix, highest priority first

- 🟡 **ID-ACCESS** (medium) Identity · Access Management — Roles limit what a key can reach and lockout bounds abuse, so access is scoped at provisioning; it is not yet just-in-time / just-enough. **Next:** Add just-in-time, just-enough access that expires, instead of standing role grants.
- 🟡 **ID-STORE** (medium) Identity · Identity Stores — Service identities and roles live with the gateway, and Open WebUI can trust a verified sign-in header on loopback; there is no central IdP wired by default. **Next:** Offer optional OIDC sign-in through the gateway's identity so one IdP backs every surface (tracked as studio-harden / gateway identity).
- ⬜ **DV-ACCESS** (low) Devices · Resource Access (device-based) — Access decisions do not yet consider the requesting device's posture. **Next:** Let the edge consider a device-posture signal before granting access to estate surfaces.
- 🟡 **DA-CAT** (low) Data · Data Categorization — Data is classified where it drives a decision — PII and secrets are recognised by the rails, and residency marks India-local data — but there is no general labelling scheme. **Next:** Add explicit sensitivity labels that follow data through the estate.
- 🟡 **DA-INV** (low) Data · Data Inventory Management — The estate knows its sensitive data where it matters — India identity numbers (Aadhaar/PAN) are detected, secret columns are dropped on import, and storage is bounded by tier — but there is no full data catalogue. **Next:** Add a lightweight data catalogue that lists where each class of data lives and its retention tier.
- 🟡 **DV-ASSET** (low) Devices · Asset & Supply Chain Risk Management — Strong for the estate's SOFTWARE supply chain — third-party code is vetted and pinned, and anything new is inspected in a sandbox before trust — but device/hardware inventory is the organisation's. **Next:** Device and hardware asset inventory remains an organisation/MDM responsibility, outside this box.
- 🟡 **ID-RISK** (low) Identity · Risk Assessments — Behavioural signals (request bursts, odd-hour activity) raise an alarm; a new model alone no longer does. There is no continuous, real-time identity-risk score. **Next:** Add a continuous identity-risk score that adjusts access as signals change.

# 20 — Claude-subscription parity (the sovereign equivalents)

You asked to be sure you can do, inside your own estate, the things a Claude subscription gives you
— **Projects, Artifacts, Code, Design, Customize, Routines** — plus **Manus/Clawbot-style
autonomous web agents**. This maps each one to its **sovereign, local-first, free** equivalent:
what's already running, how to use it, and where a gap is honestly a gap.

> The guiding rule: parity on *capability*, not on *vendor*. Everything below runs on your box
> (or a box you own), through the guardrail gateway, at ₹0 of recurring cost and zero Claude
> credits — with the cloud as an opt-in, capped fallback (doc 15).

## Routines — the sovereign scheduler (shipped in this estate)
Lighter than n8n and fully code-first: one config file, plain cron on your box, auditable, offline.

```bash
./securax routines list      # show configured jobs (routines/jobs.json)
./securax routines due       # what WOULD run right now — no execution
./securax routines run       # run everything due now
```
Drive it with **one** real cron line (Linux/macOS), then forget it:
```
* * * * * cd /path/to/estate && ./securax routines run >> routines/.log 2>&1
```
Each job in `routines/jobs.json` is `{id, cron (5-field), command (argv list — no shell, no
injection), description, enabled}`. Shipped examples: a weekday **morning brief** (`./securax
doctor`), a Monday **security-posture** run (`./securax demo`), and a Saturday **autonomous
regulator-scan** via the research agent (disabled by default — enable when you want it). The runner
de-dupes within a minute, survives a job crash, and records state in `routines/.state.json`
(git-ignored, per-box). Tested offline in `routines/tests/`.

## Opt-in extensions (shipped, off by default)
- **Image/visual generation ("Design").** A sovereign text-to-image client (`design/`) speaks your
  own **AUTOMATIC1111/ComfyUI** server; `./securax design "…"` or MCP `image_generate` saves PNGs
  to `design/out`. The server itself is a separate compose overlay (`local/compose/design.yml`,
  profile `design`) so it **never affects default startup** — enable it only if you want it (a GPU
  makes it usable; CPU works but is slow).
- **Render engine + approved-action executor (Manus writes).** The research agent can now render
  JS-heavy pages (`--render`, headless Chromium, every request allowlist/SSRF-gated) and **execute
  one approved web action at a time** (`./securax act … --approve`, every gate re-validated, full
  audit trail, no stored creds, no MCP tool). See [doc 19](19-AUTONOMOUS-RESEARCH.md).

## Remaining honest gap
- **Interactive artifact runtime.** The estate serves *static* generated HTML (fully viewable,
  shareable). It does not sandbox-execute arbitrary generated apps the way claude.ai does; for that,
  run the generated code locally in the estate where you control the sandbox.

## Why this is the better trade for you
Running BFSI security, the sovereign versions win where it matters: **RED-tier data never leaves the
machine**, there is **no per-seat/usage bill**, every AI path is **guarded and auditable**, and you
are **not locked to one vendor** — any model or tool swaps behind the standard interfaces
([doc 17](17-ENTERPRISE-ARCHITECTURE.md)). You trade a little polish for ownership, privacy and ₹0
recurring cost — and you keep Claude for the frontier work where it's genuinely worth the credits.
